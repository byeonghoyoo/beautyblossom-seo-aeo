# 복수 title의 출력 형태 분류

검토일: 2026-09-06. 대상은 2026-09-05에 보관한 공개 응답 자료입니다. 이번에 관리자 원문을 추가로 열거나 사이트를 수정하지 않았습니다.

## 작업량과 영향 범위를 나눕니다

- 수정 후보 단위: **언어 + 위젯 ID 조합 143개**. 기존 추가 title 위치 143행과 일대일 대응합니다.
- 영향 범위: **77페이지**. 전체 공개 HTML 분석 집합은 479 URL입니다.
- 한 페이지에 문제 위젯이 2개 이상인 경우: **22페이지**.
- 페이지별 문제 위젯 분포: 1개 55페이지, 2개 7페이지, 3개 3페이지, 4개 2페이지, 5개 7페이지, 7개 2페이지, 8개 1페이지.

77페이지를 77건의 수정으로 간주하지 않습니다. 143위젯의 수정 상태와 77페이지의 영향 검수를 함께 추적합니다.

## 출력 형태별 분류

| 형태 | 요소·위젯 수 | 관찰 기준 |
|---|---:|---|
| document_bundle | 139 | 해당 위젯에서 title 앞에 DOCTYPE·html·head, 뒤에 body 시작 태그가 확인됨 |
| partial_document | 4 | DOCTYPE·html·head는 있으나 해당 범위에서 title 뒤 body 시작 태그가 확인되지 않음 |
| title_fragment | 0 | 위 문서 시작 태그 없이 title만 포함된 경우 |

139/143은 약 **97.2%**입니다. 이를 공통 수정 절차를 설계할 근거로 사용합니다. 관리자 템플릿 공유 여부가 미확인이라는 이유로 설계를 미루지 않습니다.

| 언어 | document_bundle | partial_document | 합계 |
|---|---:|---:|---:|
| 한국어 | 45 | 0 | 45 |
| 영어 | 21 | 2 | 23 |
| 일본어 | 22 | 1 | 23 |
| 간체 | 22 | 1 | 23 |
| 번체 | 29 | 0 | 29 |
| 합계 | 139 | 4 | 143 |

## 지금 설계할 공통 수정 절차

1. 위젯 ID로 관리자 입력 원문을 확보하고 공개 출력의 해당 title과 대조합니다.
2. 플랫폼의 정상 문서 제목은 보존하고, 위젯 안의 불필요한 title만 제거하는 최소 변경안을 우선 만듭니다.
3. head 전체, body·html 속성, style·script·link는 자동 삭제하지 않습니다. 속성·스타일·리소스·실행 의존성이 있는지 확인합니다.
4. DOCTYPE·html·head·body 등 나머지 문서 포장 태그의 정리는 별도 변경으로 검토합니다. 같은 시작 태그가 있다는 사실만으로 제거 안전성까지 같다고 보지 않습니다.
5. 두 출력 유형과 주요 의존성 변형에서 대표 시험을 통과한 뒤 검증된 절차를 해당 위젯 묶음에 적용합니다. 차이가 없는 항목을 143개의 독립된 설계로 반복하지 않습니다.
6. 실제 반영은 작은 묶음으로 진행하고, 해당 페이지의 다른 문제 위젯과 상호작용을 함께 검사합니다. 22개 다중 문제 페이지를 회귀 검사에서 빠뜨리지 않습니다.

**분류·공통 절차 설계는 지금 가능**, **관리자 원문에 대한 자동 일괄 삭제는 아직 승인 불가**입니다. 이는 다른 판단입니다.

## 재현 방법과 증거

입력은 기존 title 위치표와 코드 위젯 목록입니다. 각 행의 위젯 시작 위치에서 다음 외부 위젯 시작 전까지를 보관한 HTML 텍스트에서 찾아 title 1개가 포함됐는지 확인하고, 앞뒤 문서 시작 태그의 존재로 분류했습니다. 정규화된 위젯 조각은 파서가 문서 태그를 제거할 수 있어 형태 판정에 사용하지 않았습니다.

분류표의 `source_archive_sha256`은 저장된 압축 파일의 해시이며 기존 원본 해시 목록과 대조했습니다. 수집 당시 응답 바이트의 해시와, 텍스트를 다시 인코딩해 압축한 파일의 해시는 다른 값이므로 혼용하지 않습니다. `rendered_sha256`은 기존 위젯 목록의 정규화된 출력 지문으로, 같은 출력 그룹을 비교하는 데만 사용합니다.

이 검사는 공개 출력의 형태를 확인한 것입니다. 문서 전체의 올바른 중첩, 관리자 입력 원문의 동일성, 모든 태그 삭제의 안전성을 보증하지 않습니다.
