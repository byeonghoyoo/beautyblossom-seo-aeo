# 수정 전 코드 리뷰 — 아임웹 SEO·AEO

2026-09-05 · 읽기 전용 감사 · 사이트 변경 없음

## 1. 관리자 공통 코드 배치

다음은 실제 입력 영역에서 읽은 글자 수다. 네트워크 전송 바이트 또는 성능 측정값이 아니다.

| 언어 | Header Top | Header | Body | Footer | 보호할 주요 코드 |
|---|---:|---:|---:|---:|---|
| 한국어 | 1,635 | 1,817 | 61,907 | 7,446 | Body의 v13.26 메뉴·검색·스타일, 추적·연락 UI |
| 영어 | 549 | 17,602 | 61,345 | 6,772 | Body의 v13.21 영문 메뉴·검색, Header의 갤러리 효과 |
| 일본어 | 18,133 | 58,284 | 633 | 7,254 | Header에 저장된 대형 메뉴·검색·스타일 |
| 간체 | 18,061 | 57,580 | 633 | 12,115 | Header의 대형 UI 코드, Footer 연락 UI |
| 번체 | 17,212 | 57,437 | 633 | 12,115 | Header의 대형 UI 코드, Footer 연락 UI |

일본어·간체·번체는 '바디코드' 성격의 큰 블록이 Header 입력 영역에 있다. 이름만 보고 Body로 이동하면 실행 순서·스타일 적용 시점이 달라질 수 있다. **재배치·재정렬·공통화하지 않는다.** Google·네이버 인증, GA 계열 추적, 상담 링크 이벤트, Beusable, 폰트·아이콘도 별도 검증 없이 삭제하지 않는다.

5개 관리자 메뉴 트리에서 확인한 노드 수는 한국어 125, 영어 124, 일본어 125, 간체 128, 번체 125다. 폴더·시스템·공통·모달 등이 포함되므로 공개 페이지 수로 해석하지 않는다.

## 2. 리뷰 R1 — hreflang 자동 생성

위치: 영어 Header Code 500–521행 / 일본어·간체 Header Top Code 517–538행.

현재 원문에서 확인한 핵심:

```javascript
var path = window.location.pathname + window.location.search;
// langs에 국가별 도메인을 지정
link.href = 'https://' + langs[i].host + (langs[i].isThailand ? '/' : path);
document.head.appendChild(link);
```

이 코드의 결과로 영어 `/107`에서 한국어·간체·번체 `/107`을 연결한다. 해당 세 URL의 응답은 404다. 올바른 소프웨이브 URL 번호는 한국어 139, 영어 107, 일본어 107, 간체 108, 번체 139다.

변경 이유: 도메인만 바꿔도 같은 페이지라는 가정이 실제 정보구조와 맞지 않는다. URL의 검색 파라미터까지 복제하도록 작성되어 있는 것도 확인했다. 파라미터별 실제 검색 영향은 별도 확인 전 단정하지 않는다.

영향 범위: 검색엔진의 언어 대응 관계. 사용자에게 보이는 국가 선택 메뉴의 href는 별도 코드이므로 같이 바꾸지 않는다.

검토할 최소 변경: 검증된 시술별 대응표로 대체하고, 동일 페이지의 메타데이터 생성 주체를 하나로 통일한다. 아임웹에서 지원하는 삽입 위치를 확인한 뒤 실제 diff를 작성한다. HEAD 삽입 지원을 확인하지 않은 상태에서 위젯 DIV에 태그를 추가하는 코드를 납품하지 않는다.

## 3. 리뷰 R2 — 위젯 안의 완전한 HTML 문서

한국어 보톡스 `/28`, 위젯 `w202502093504b04ef7753`. 보존된 원본 HTTP 응답 13625행에 아래 title이 있다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>보톡스 시술 부위</title>
</head>
<body>
    <div class="iamweb_injection_container">
```

아임웹이 이미 만드는 문서 안에 별도 문서가 삽입된 구조다. 브라우저는 두 번째 title을 DIV 안에 남겼다. 이 조각은 **공개 응답에서 확인한 원문**이며 해당 위젯 편집기의 현재 미게시 원문 전체를 대체하는 복원본은 아니다.

변경 이유: 위젯의 보조 제목을 문서 title로 출력할 이유가 없다. 정상 문서 title을 아임웹 SEO 설정 한 곳에서 관리하도록 정리할 대상이다.

영향 범위: 문서 메타데이터와 파싱 구조. 화면의 번호·시술 부위·레이아웃과는 분리해서 수정해야 한다.

검토할 최소 변경: 우선 중복 title만 제거하는 단위부터 검증한다. `iamweb_injection_container`와 내부 DOM, 클래스·ID, CSS, 이미지, JS는 유지한다. viewport와 html/body 래퍼까지 제거할 경우 별도 단계로 검수한다. 모바일 레이아웃 변화가 없는지 확인 전 일괄 정리하지 않는다.

주의: 숨겨진 중복 title이 제거되어도 시각 변화가 없을 것이라는 가정만으로 완료 처리하지 않는다. 실제 viewport·스타일·DOM 비교가 필요하다.

## 4. 리뷰 R3 — 실리프팅에서 SEO 코드 소유권 중복

영어 `/thread-lifting`, 위젯 `w20260606600bb8a29ee20`.

- 정상 title과 위젯 title이 중복된다.
- HEAD에서 생성된 hreflang 7개와 DIV의 정적 hreflang 6개가 함께 존재한다.
- HEAD x-default는 한국어 시술 페이지, DIV x-default는 영어 시술 페이지다.
- DIV의 한국어 링크만 www 도메인을 사용하며, 그 URL의 canonical은 www 없는 주소다.

변경 이유: 같은 검색 신호의 관리 지점이 분산되어 서로 다른 값을 내보낸다.

영향 범위: 검색 메타데이터. 실리프팅 페이지의 영상, 전후 비교, FAQ, 상세 레이아웃은 수정 대상이 아니다.

검토할 최소 변경: 메타데이터를 한 세트로 통일하고 유효한 HEAD에 위치시키는 방식을 검증한다. 기존 전역 코드를 지우기 전에 다른 페이지의 언어 연결이 사라지는지를 전체 대응표로 확인한다. x-default 선택도 사이트 정책으로 명시하고 통일한다.

## 5. 수정 금지 및 보류

- 전역 CSS 리팩터링, 공통 코드의 Header↔Body 이동, 폰트/아이콘/슬라이더 제거는 금지한다.
- viewport 변경, H1 교체, alt 대량 변경은 '보이지 않는 코드'라는 이유만으로 안전하다고 분류하지 않는다. 시각·접근성 영향 검증이 필요하다.
- 순위 조작용 숨김 문구, 사용자에게 없는 FAQ·효능·평점·후기·가격을 JSON-LD에만 추가하지 않는다.
- 현재 JSON-LD는 파싱 오류가 없으므로 '스키마 오류 전면 교체'는 근거가 부족하다. 속성·사실·출력 중복을 별도로 검수한다.
- robots의 반복 줄만 보고 전체 교체하지 않는다. 아임웹 자동 기본 규칙과 사용자 추가 규칙의 최종 출력이 기준이다.
- 관리자 원문 백업·시험 방법·성능 기준선이 준비되기 전 라이브 수정 승인을 요청하지 않는다.

## 6. 아직 납품하지 않은 것

이 문서는 코드 리뷰이지 적용 가능한 최종 패치가 아니다. 실제 관리자 원문 백업, 전체 언어 매핑, 아임웹 삽입 위치 검증, 회귀 기준선이 남아 있다. 이를 확보한 뒤에만 파일/필드별 변경 전후 diff와 복원본을 제공한다.
