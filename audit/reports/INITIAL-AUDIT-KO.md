# 뷰티블라썸 아임웹 SEO·AEO 1차 진단 및 개선안

확인일: 2026-09-05 · 대상: 한국어·영어·일본어·중국어 간체·번체 · 태국어 제외

## 결론

우선순위는 새로운 SEO 코드를 대량으로 추가하는 것이 아니라, 이미 출력되는 검색 신호의 잘못된 연결·중복·불일치를 바로잡는 것이다. 확인된 핵심은 **잘못된 다국어 URL, 위젯의 중복 제목 태그, 홈페이지 대표 URL 분산, 검색 설명문 출력 문제**다.

사이트 코드·설정의 저장, 게시, 권한 변경은 하지 않았다. 아래는 수정 전 검토안이며 적용된 결과가 아니다. 검색 순위 하락 원인이나 개선 폭은 검색 성과 데이터 없이 단정하지 않는다.

## 1. 확인 범위와 한계

| 언어 | 공개 도메인 | 요청 URL 수 | 중복 제거한 일반 HTML 최종 URL | 복수 title URL |
|---|---|---:|---:|---:|
| 한국어 | [beautyblossom.kr](https://beautyblossom.kr/) | 106 | 97 | 18 |
| 영어 | [en.beautyblossom.kr](https://en.beautyblossom.kr/) | 106 | 94 | 16 |
| 일본어 | [jp.beautyblossom.kr](https://jp.beautyblossom.kr/) | 107 | 97 | 16 |
| 간체 | [cn.beautyblossom.kr](https://cn.beautyblossom.kr/) | 108 | 98 | 16 |
| 번체 | [tw.beautyblossom.kr](https://tw.beautyblossom.kr/) | 103 | 93 | 11 |
| 합계 | 5개 언어 | 530 | 479 | 77 |

530은 사이트맵 URL에 각 루트 URL을 추가한 요청 수다. 외부 네이버 예약으로 이동한 응답 3개, 상품 구매 불가 안내 스크립트만 반환한 응답 10개를 일반 콘텐츠 분석에서 분리했다. 나머지 517개 응답에서 동일 최종 URL 중복 38개를 제거해 479개를 분석했다. 모든 요청의 최종 HTTP 200이 모든 경로의 정상 콘텐츠를 뜻하지 않는다.

확인한 항목:

- 5개 관리자 SEO 설정의 robots·llms·Header Top·Header·Body·Footer, 총 30개 입력 영역을 읽었다. 국가별 디자인 메뉴 트리도 확인했다.
- 공개 페이지의 원본 응답, 메타데이터, canonical, hreflang, JSON-LD, 제목 구조, 이미지 속성, 링크 및 코드 위젯을 추출했다.
- 479개 URL에 코드 위젯 출현 1,976건, 서로 다른 출력 HTML 조각 1,496개를 정리했다. 전역 위젯이 여러 페이지에서 반복되므로 원본 위젯 개수와 같지 않다.
- 이미지 출현 11,780건과 제목 요소 출현 8,636건을 목록화했다. 이미지 픽셀 내용·OCR·모든 모바일 화면을 전수 판독했다는 뜻은 아니다.
- 5개 언어 홈 및 한국어 보톡스·영어 소프웨이브·영어 실리프팅은 브라우저 실행 후 DOM도 대조했다.

아직 확인하지 않은 항목:

- 비게시·숨김·사이트맵 밖의 모든 페이지 및 모든 관리자 위젯 편집기 원문을 전수 확인하지는 않았다. 관리자 원문 열기는 표본 점검이다.
- 공개 출력 HTML은 보존했지만 관리자 입력 코드 전체의 **복구 가능한 백업 파일**은 아직 완성하지 않았다. 브라우저에서 읽은 원문과 공개 출력 소스는 서로 다를 수 있다.
- Search Console·네이버 서치어드바이저의 실제 색인·노출·클릭·선택 canonical, 검색 순위, AI 인용 실적은 미확인이다.
- 실사용 Core Web Vitals와 동일 조건 반복 성능 측정, 모바일·PC 시각 회귀, 예약·메뉴·슬라이더 기능 회귀 검증은 아직 수행하지 않았다.

## 2. 확인된 문제와 우선순위

### P1-01. 다국어 연결 코드가 없는 페이지를 가리킨다

영어 Header Code 500–521행, 일본어·간체 Header Top Code 517–538행은 현재 `pathname + search`를 다른 국가 도메인에 그대로 붙여 hreflang을 생성한다. 그러나 같은 시술의 URL 번호가 국가마다 다르다.

| 소프웨이브 언어 | 영어 페이지가 생성한 연결 | 그 URL의 HTTP 상태 | 실제 시술 페이지 |
|---|---|---:|---|
| 한국어 | `/107` | **404** | [/139](https://beautyblossom.kr/139) |
| 영어 | `/107` | 200 | [/107](https://en.beautyblossom.kr/107) |
| 일본어 | `/107` | 200 | [/107](https://jp.beautyblossom.kr/107) |
| 간체 | `/107` | **404** | [/108](https://cn.beautyblossom.kr/108) |
| 번체 | `/107` | **404** | [/139](https://tw.beautyblossom.kr/139) |

브라우저에서 생성된 실제 링크와 별도 HTTP 응답을 대조했다. 한국어·번체 홈에는 렌더링 이후에도 hreflang이 없고, 영어·일본어·간체 홈에는 각각 7개가 있다. 따라서 “모든 언어에서 hreflang이 없다”는 진단은 틀리다.

영어 실리프팅은 공통 코드가 만든 HEAD의 7개와 위젯 DIV 안의 6개가 함께 존재한다. `x-default`는 한국어와 영어로 갈리고, 한국어 주소는 www 유무도 다르다. Google은 대응 콘텐츠의 상호 연결과 유효한 HEAD 위치를 요구한다. [Google 다국어 지침](https://developers.google.com/search/docs/specialty/international/localized-versions)

**개선안:** 실제 시술별·언어별 대응표를 먼저 확정하고, 검증된 URL만 한 곳에서 관리한다. 동일 경로 자동 복제는 폐기 후보다. 아임웹에서 페이지별 HEAD 또는 사이트맵 제어가 실제 가능한지 확인한 뒤 구현 방식을 결정한다. 페이지 본문 위젯에 SEO 태그를 더 얹거나, 전역 JS를 또 추가하는 방식으로 확정하지 않는다. 태국어 사이트 자체는 수정하지 않는다.

### P1-02. 77개 URL의 위젯에서 문서 제목이 추가 출력된다

공개 소스에서 77개 URL에 복수 `<title>`이 있고, 첫 번째 제목 외에 추가 제목 요소가 143개다. 같은 태그의 문자열이 같은지 여부와는 별개로 문서 구조 문제다.

- 한국어 보톡스 `/28`: HEAD의 정상 제목 외에 DIV 안에 `보톡스 시술 부위`가 있다. 위젯 ID는 `w202502093504b04ef7753`이다.
- 영어 소프웨이브 `/107`: 정상 영어 제목 외에 한국어 `시술 전후 비교`가 있다. 위젯 ID는 `w20250713df0e94da60995`다.
- 한국어 소프웨이브 `/139`: 원본 응답에 제목 요소가 총 9개다.

보톡스 원본 응답에는 코드 위젯 안에 `<!DOCTYPE html>`, `<html>`, `<head>`, `<title>`, `<body>`로 이루어진 별도 문서가 삽입되어 있다. 보톡스·영어 소프웨이브는 브라우저 DOM에서도 중복을 재확인했다. 현재 브라우저 `document.title`은 정상 첫 제목이다. 실제 검색 제목이 잘못 노출된다고 확인한 것은 아니다. [Google 제목 지침](https://developers.google.com/search/docs/appearance/title-link), [네이버 콘텐츠 마크업](https://searchadvisor.naver.com/guide/markup-content)

**개선안:** 아임웹이 만드는 정상 문서 제목을 유지하고 위젯의 불필요한 문서 메타데이터만 제거하는 최소 변경을 검토한다. 시각 요소·CSS·스크립트·ID는 보존한다. 특히 viewport·문서 래퍼는 모바일 렌더링에 영향을 줄 수 있으므로, title 제거와 일괄 묶어 무검증 삭제하지 않는다.

### P2-01. 홈 `/`와 `/home`이 동일한 콘텐츠를 각각 대표 URL로 선언한다

5개 언어 모두 두 URL이 HTTP 200이며, 위젯 ID·종류·텍스트의 전체 순서가 일치한다. 그런데 `/`는 `/`를, `/home`은 `/home`을 canonical로 선언한다. 이는 같은 홈페이지에 대한 대표 URL 신호를 통일할 검토 근거다. 두 URL이 모두 실제 색인되었거나 불이익을 받았다는 증거는 아니다. [Google canonical 지침](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

**개선안:** 기존 유입·색인·사이트맵·내부 링크를 확인해 언어별 대표 홈 URL을 결정한다. 결정 전 임의로 `/home` 삭제나 리디렉션을 적용하지 않는다. 화면과 이동 기능은 그대로 유지하는 대표 URL 정합성 수정부터 검토한다.

반대로 아임웹 기본 도메인 5개는 HTTP 200이지만 모두 사용자 도메인으로 canonical이 이미 설정되어 있다. 따라서 기본 도메인이 열린다는 이유만으로 “중복 색인 오류 확정”이라고 판단하거나 검색 허용을 즉시 끄지 않는다.

### P2-02. 검색 설명문에 키워드 나열과 입력·출력 불일치가 있다

한국어 홈 description은 `홍대피부과, 합정피부과, 홍대보톡스…` 형태의 키워드 나열이다. 네이버는 페이지 내용을 요약한 설명을 권장하고 단순 키워드 나열을 지양한다. [네이버 콘텐츠 마크업](https://searchadvisor.naver.com/guide/markup-content)

영어 홈은 관리자 입력이 `natural results. Learn more today.`로 끝나지만, 공개 HTML과 브라우저 meta는 `natural re...`로 끝난다. **검색 결과에서 줄여 표시된 현상이 아니라 사이트 출력 단계에서 이미 다른 문자열**임을 확인했다. 내부 절단 로직과 정확한 출력 상한은 아직 확인하지 않았다.

**개선안:** 이미 공개되어 검증 가능한 병원·위치·진료 범위만으로 간결한 설명을 작성한다. 임의 글자 수 SEO 규칙을 적용하지 않고 아임웹의 실제 출력 결과로 완결성을 확인한다. 본문·디자인은 바꾸지 않는다. 허가·효능·안전성·가격을 새로 지어내지 않는다.

### P2-03. 사이트맵에 콘텐츠가 아닌 상품 경로가 포함되어 있다

5개 언어 각각의 `/shop_view/1`, `/shop_view/2`, 총 10개 URL은 HTTP 200이지만 구매 불가 알림과 `history.go(-1)` 스크립트만 반환한다. 479개 일반 콘텐츠 URL 집계에서는 제외했다. 검색엔진이 이미 soft 404로 판정했다고 확인한 것은 아니다.

**개선안:** 이 상품 경로를 검색에 노출할 사업 목적이 있는지 확인하고, 불필요하면 아임웹의 사이트맵·검색 노출 생성 설정에서 제외할 수 있는지 조사한다. 상품·페이지 자체를 삭제하지 않는다. 정상 예약 이동 3개도 오류로 일괄 제거하지 않는다.

## 4. 이번 프로젝트의 고정 설계 조건

### PRD: 무엇을 달성하고 무엇을 하지 않는가

목표는 Google·네이버가 기존 콘텐츠의 주제·대표 URL·언어 관계·병원 정보를 모순 없이 해석하도록 만드는 것이다. 성공 여부는 수정 대상 신호의 정확성과 디자인·기능·속도 보존을 먼저 기준으로 삼는다. 순위·AI 인용 증가를 코드 수정만으로 보장하지 않는다.

비목표: 리디자인, 메뉴 재개발, 본문 재작성, 대량 키워드 삽입, 숨겨진 SEO 문장·H1 추가, 예약 흐름 변경, 폰트·슬라이더·애니메이션 제거, 사이트 이전, 새 SEO 라이브러리 설치.

### 기술스택 및 책임 분리

아임웹의 기존 네이티브 SEO 설정과 HTML 메타데이터·canonical·hreflang·JSON-LD를 사용한다. 새 프레임워크·플러그인을 전제로 하지 않는다. 기존 CSS·JS와 아임웹 자동 출력은 보존하며, 아임웹에서 지원하지 않는 서버 제어를 가능하다고 가정하지 않는다.

관리 기준은 `실제 페이지 대응표 → 네이티브 SEO 설정/검증된 삽입 위치 → 원본 HTML → 실행 후 DOM`이다. 같은 태그를 공통 코드와 페이지 위젯이 중복 소유하지 않도록 한다. 모든 변경은 국가·페이지·위젯·필드·원문·변경 이유·영향 범위·복원본과 연결한다.

### 적용 전 필수 통과 조건

1. **복구:** 실제 수정할 관리자 원문과 설정을 파일로 보관하고 복원 위치까지 확인한다. 공개 HTML 백업을 관리자 복원본으로 혼동하지 않는다.
2. **코드 검수:** 변경 전후 diff를 먼저 사용자에게 제시한다. CSS, UI DOM, 글꼴, 이미지, 이벤트 연결 등 보호 영역이 달라지면 보류한다.
3. **SEO:** 정상 title과 canonical, 실제 200인 대응 페이지, 언어별 상호 연결, 불필요 쿼리 미전파, JSON 문법과 화면 내용 일치 여부를 확인한다.
4. **디자인:** 같은 URL·브라우저·화면 크기·스크롤·대기 조건에서 모바일과 PC의 변경 전후를 비교한다. 움직이는 영상 등 자연 변동을 구분하되 변경으로 인한 시각 차이는 허용하지 않는다.
5. **기능:** 메뉴·검색·언어 이동·슬라이더·FAQ·상담 링크의 동작을 비교한다. 실제 예약 제출·메시지 전송·구매는 수행하지 않는다.
6. **속도:** 외부 요청·새 스크립트·타이머·DOM 탐색 루프를 추가하지 않는 것을 기본으로 한다. 같은 네트워크/기기 조건의 반복 측정으로 LCP·CLS·로딩/실행 비용을 대조하고 상호작용 반응도 확인한다. 측정 변동은 재검사하며 **악화가 없음을 확인하지 못하면 승인하지 않는다.** Lighthouse 점수 하나로 무회귀를 선언하지 않는다.
7. **적용:** 검수 가능한 시험 환경이 확보된 뒤 최소 단위로 검증한다. 초안 저장이 공개 사이트에 즉시 반영되는지부터 확인한다. 사용자의 명시적 승인 전 저장·게시하지 않는다. 문제 발견 시 추가 수정을 덧붙이지 않고 검증된 원문으로 복원한다.

### Claude Code 구현 지시문 초안 — 아직 실행하지 않음

> 승인된 항목과 대상 코드만 수정한다. 라이브 아임웹 관리자에서 자동 저장·게시하지 않는다. 관리자 원문을 먼저 확보하고 파일별 diff를 제시한다. 한국어로 이유와 영향 범위를 설명한다. 디자인 DOM·CSS·기능 스크립트·추적 코드·리소스 로드 순서를 변경하지 않는다. 신규 외부 라이브러리나 전역 실행 루프를 추가하지 않는다. hreflang은 검증된 시술별 URL 대응표만 사용한다. title·canonical·JSON-LD의 출력 결과를 확인하고 모바일·PC 화면, 상호작용, 반복 성능 비교 결과를 제출한다. 플랫폼 제약이나 의료 사실의 불명확성이 있으면 임의로 해결하지 말고 보고한다. Codex 검수와 사용자 승인 전에 적용 완료를 선언하지 않는다.

## 5. AEO에 대한 냉정한 판단

이번 범위에서 AEO는 보이지 않는 특별 태그를 많이 추가하는 작업이 아니다. 기존의 정확한 콘텐츠를 검색엔진이 수집·색인·해석할 수 있게 하고, 페이지와 구조화 데이터가 같은 사실을 말하도록 만드는 작업이다. Google의 현행 공식 지침은 별도 LLMS.txt나 특별 AI 마크업을 검색 노출 필수요건으로 보지 않으며, LLMS.txt는 Google 검색 순위에 도움이 되거나 해가 되지 않는다고 설명한다. 따라서 현재 llms 입력 영역 개선은 위의 실제 오류보다 후순위다. [Google 생성형 AI 최적화 지침](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)

이 Google 지침을 네이버의 AI 시스템 동작 보장으로 확대하지 않는다. 네이버에는 확인 가능한 콘텐츠 마크업·수집·색인 기준을 적용하고, AI 채택 여부는 별도 관측 대상이다. 이미지에만 있는 설명을 새 본문으로 만들거나 의료 콘텐츠를 고치는 작업은 이번 '보이지 않는 기술 수정'과 분리해서 승인받아야 한다.

## 6. 검수 로그와 근거 파일

- 원인 재현: 영어 소프웨이브의 3개 잘못된 언어 대상 HTTP 404, 위젯의 복수 title, 실리프팅의 HEAD/DIV hreflang 충돌 확인.
