## 작업 목록

- [ ] -1 / R01: 언어별 제어 범위를 실측합니다. canonical의 A·B·C·미확인 상태를 구분하고 4A의 실행 경로를 결정합니다. 저장이 필요한 확인은 백업·격리·사전 승인 없이는 하지 않습니다.
- [ ] 0 / R02: 변경 대상 원문을 비공개 로컬 보관 위치에 확보합니다. UTF-8 원문, 메타데이터, 해시, 복구 안내와 2차 사본을 검증합니다. 공개 저장소에는 안전하게 검토한 색인만 둡니다.
- [ ] 1 / R03: PC·모바일 화면과 비제출 기능을 기록하고 전후 비교용 5회 성능 기준선을 준비합니다.
- [ ] 2 / R04: 대응표와 hreflang 정책을 대조합니다. 첫 시험은 소프웨이브 5언어 묶음이며 x-default는 필수 완료 항목이 아닌 운영 정책을 따릅니다.
- [ ] 3 / R05: 기존 143위젯 출력 분류를 바탕으로 공통 수정 절차를 설계하고 관리자 원문과 대조합니다. 최소 title 수정, 유형별 시험, 작은 묶음 적용, 페이지 회귀 검수 순서로 진행합니다.
- [ ] 4 / R06: 대표 주소 4A는 실측 게이트에 따라 진행·대안 검증·보류합니다. 설명문 4B는 독립 검토합니다. 추가 canonical 삽입으로 자동 태그를 덮으려 하지 않습니다.
- [ ] 5 / R07: 구조화 정보와 화면의 사실을 맞추고, 별도 네이버 기술 검증 트랙의 5호스트 등록·수집·사이트맵·해당 RSS·제출 상태를 기록합니다.
- [ ] 6 / R08: 이미지 후보 최대 3개를 선정하고 사용 권한·제작일 근거를 확인합니다. 승인된 한 위치의 시안·시험까지만 초기 일정에 포함합니다.
- [ ] 7 / R09: 479 URL 재검사와 143위젯 상태를 대조합니다. 기술 정상화, 플랫폼 미해결, 검색엔진 관찰 대기를 나누어 인계합니다.

## 변경 패키지

공개 가능한 패키지에는 변경 ID, 대상 언어·URL·위젯/필드, 문제 근거, 최소 diff, 보존 요소, 승인 기록, 검사 원자료 또는 비공개 증거 ID, 복구본 ID, 미해결 위험을 담습니다.

관리자 원문 전체를 before.txt나 rollback.txt라는 이름으로 공개 Git에 커밋하지 않습니다. 원문 파일은 실행·검수 기준에 정한 비공개 위치에서 관리합니다. 코드를 구현할 때 필요한 검사기는 해당 PR에서 실제로 만들고 실행한 뒤 결과를 기록합니다. 문서에 적힌 예상 PASS를 실제 결과로 보고하지 않습니다.

## 시험·완료 판정

- 실행 전: 원문 대조, 복구 가능성, 변경 전 리뷰, 격리 공간과 사전 승인.
- 실행 후: 의도한 검색 정보, PC·모바일 화면, 주요 기능, 각 전후 5회 중앙값.
- 반려: LCP +10% 초과, CLS 0.1 초과, 또는 그 이하의 재현 가능한 악화·기능/화면 이상.
- 증거 부족: 보류. 성공으로 기록하거나 다음 페이지로 자동 확대하지 않음.
- 다국어: 5개 언어 묶음 전체 검증을 내부 완료선으로 사용하되 개별 검증 진행률도 기록.
- 최종: 복수 title 77페이지→0, 추가 title 143요소→0 목표. 미검사·미해결을 분모에서 제외하지 않음.
- 검색 반영: GSC·네이버의 관측 자료로 별도 판단. 순위나 인용 증가 보장 없음.

## 저장소 검증 명령

현재 저장소에서 실제로 존재하는 검사만 나열합니다.

```powershell
python -X utf8 -m compileall -q tools tests
python -X utf8 -W error::ResourceWarning -m unittest discover -s tests -v
git diff --check
```

이 검사는 문서·데이터의 일관성을 확인합니다. 라이브 홈페이지 성능·디자인·동작의 통과 증거로 사용할 수 없습니다.
