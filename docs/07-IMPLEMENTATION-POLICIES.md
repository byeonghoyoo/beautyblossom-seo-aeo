## 1. -1단계: 아임웹 제어 가능 범위 실측

아임웹은 제목·설명의 기본 설정을 제공하고 canonical을 자동으로 생성한다고 안내합니다. 그러나 이 안내만으로 특정 사이트에서 canonical을 변경할 수 있다거나 없다고 결론 내릴 수 없습니다. 공통 코드 삽입 기능도 플랫폼이 생성한 태그를 자유롭게 수정할 수 있다는 뜻은 아닙니다. [아임웹 SEO 안내](https://imweb.me/qna?mode=faq&q=71763), [공통 코드 안내](https://www.imweb.me/qna?mode=faq&q=71387)

아래 항목을 한국어·영어·일본어·간체·번체별로 확인합니다. 공통 기능처럼 보여도 한 언어의 결과를 나머지 네 언어에 복사하지 않습니다.

| 확인 대상 | 지금 확보한 근거 | 실측에서 남길 내용 |
|---|---|---|
| 사이트·메뉴 제목과 설명 | 공식 기능 안내, 일부 관리자 관찰과 공개 출력 | 입력 위치, 우선순위, 잘림·덮어쓰기, 최종 출력 |

| 자동 canonical | 공식 자동 생성 안내, 홈 10주소의 자기참조 출력 | 직접 수정·해제 가능 여부, 우회 설정의 지원 여부 |
| 페이지별 hreflang | 공개 출력과 일부 생성 코드 관찰 | 유효한 head 또는 사이트맵에 페이지별로 출력 가능한 경로 |
| 공통 head/body/footer | 공통 입력 필드 관찰 | 모든 페이지에 미치는 영향, 페이지별 조건 처리의 필요 여부 |
| 주소 이동·사이트맵·RSS | 일부 공개 응답, 공식 기능 안내 | 설정 가능 범위, 실제 응답, 자동 생성 항목의 수정 가능 여부 |
| 저장·미리보기·게시 | 사이트별 안전 동작 미실측 | 저장 즉시 공개 여부, 격리된 시험 공간 존재, 복구 방법 |

실측표에는 `site, capability, admin_location, evidence_id, observed_at, result, affected_scope, fallback`을 기록합니다. 결과는 `unverified / supported / unsupported / blocked`로 구분합니다. 공식 안내만 읽은 항목은 `supported`가 아니라 `unverified`에 근거를 첨부합니다.

우선 읽기 전용으로 조사합니다. 동작 확인에 저장이 필요하다면 **해당 필드의 원문을 먼저 백업하고**, 공개 사이트와 분리됐음을 확인한 시험 공간에서 사용자 승인을 받은 경우에만 시험합니다. -1단계라는 이름을 이유로 백업보다 먼저 쓰기 작업을 하지 않습니다. 격리 여부를 확인할 수 없으면 현장에서 시험하지 않고 `blocked`로 남깁니다.

단계 통과는 모든 항목이 수정 가능하다는 뜻이 아닙니다. 각 항목의 지원·제약과 안전한 경로를 입증하고, 실행할 항목에 미확인 상태가 없어야 합니다. 한 항목이 막혀도 독립된 안전 항목의 기획은 계속할 수 있습니다.

### 4A 대표 주소 작업의 의존성 게이트

실측 결과가 나오기 전에는 대표 주소 후보를 조사할 수만 있고, 그 주소를 실제로 반영할 수 있다고 전제하지 않습니다. 다음 표는 언어별로 작성합니다.

| 실측 결과 | 4A 처리 |
|---|---|
| A. 기존 자동 canonical을 편집·대체할 수 있음 | 최종 응답에 의도한 canonical 하나만 남는지 검증한 뒤 직접 수정안 진행 |
| B. 추가 삽입만 가능하고 기존 태그는 제거·대체 불가 | 추가 canonical 삽입안 금지. 지원되는 주소 이동·내부 링크·사이트맵 경로를 별도 검증 |
| C. 기존 태그 편집과 추가 삽입 모두 불가 | 태그 수정안 중단. 다른 수단도 불가한지는 별도 실측하며, 모두 불가하면 관측·지원 문의 준비만 진행 |
| U. 결과 미확인 또는 시험 불가 | 4A 실제 적용 보류. 가능·불가 어느 쪽도 추정하지 않음 |

복수 canonical 선언은 무시될 위험이 있습니다. Google의 설명은 “항상 둘 다 무시”라는 확정 규칙이 아니라 무시할 가능성에 대한 경고입니다. 이번 프로젝트에서는 위험을 감수해 추가하지 않습니다. [Google 복수 canonical 주의사항](https://developers.google.com/search/blog/2013/04/5-common-mistakes-with-relcanonical)

**태그를 못 고친다 → 내부 링크·사이트맵·주소 이동도 못 고친다**는 결론은 성립하지 않습니다. 따라서 B와 C 모두 독립 수단을 확인합니다. 내부 링크·사이트맵 정렬도 자동 canonical의 반대 신호를 확실히 덮어쓴다고 보장하지 않습니다.

### canonical을 직접 바꿀 수 없을 때

4단계 중 **대표 주소 작업을 재설계**합니다. 설명문 작업까지 일괄 폐기하지는 않습니다. 플랫폼이 지원하는 주소 이동, 내부 링크·사이트맵 정렬, 고객지원 확인을 대안으로 검토합니다. 각 대안도 실제 지원 여부와 영향을 검증하며, 문의 발송·주소 이동·삭제는 별도 승인 대상입니다.

두 번째 canonical 삽입, 브라우저 실행 후 강제 교체, 임의의 noindex 추가는 기본 대안으로 채택하지 않습니다. 안전한 방법이 없으면 플랫폼 제약으로 보류하며 해결한 것으로 계산하지 않습니다. canonical은 검색엔진에 주는 신호이고 최종 선택을 강제하지 못합니다. [Google 대표 URL 안내](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

## 2. 다국어 연결과 hreflang

방문자가 누르는 언어 이동 링크와 검색엔진용 hreflang은 따로 검사합니다. 같은 주소 표를 사용하되 하나가 정상이라고 다른 하나도 정상으로 처리하지 않습니다.

| 사이트 구분 | 이번 기본 언어 코드 | 정책 |
|---|---|---|
| kr | `ko` | 도메인 약칭 kr을 언어 코드로 쓰지 않습니다. |
| en | `en` | 특정 영어권 국가 타깃은 아직 확정하지 않습니다. |
| jp | `ja` | 도메인 약칭 jp를 언어 코드로 쓰지 않습니다. |
| cn | `zh-Hans` | 우선 간체라는 언어·문자 구분을 사용합니다. |
| tw | `zh-Hant` | 우선 번체라는 언어·문자 구분을 사용합니다. |

`zh-CN`·`zh-TW`도 유효한 표기입니다. 틀린 코드라고 일괄 치환하지 않습니다. 국가별 타깃을 명확히 운영한다는 근거가 확인되면 지역 표기로 정책을 개정합니다.

적용 규칙은 다음과 같습니다.

1. 같은 시술·역할의 페이지를 하나의 묶음으로 관리합니다. 제목, 실제 내용, 최종 URL로 대응 관계를 확인합니다.
2. 각 페이지에는 **자기 자신과 실제 존재하는 다른 언어 페이지**를 포함하고, 묶음 안의 모든 페이지가 같은 목록을 상호 참조하도록 합니다.
3. 주소는 HTTPS 절대주소로 적습니다. 최종 200 응답, 색인 가능 여부, 선택한 대표 주소와의 일치를 확인합니다. 이 프로젝트에서는 추적 쿼리·해시·중간 이동 주소를 사용하지 않습니다.
4. 같은 경로 번호를 국가 도메인에 자동 복사하지 않습니다. 번역 페이지가 없으면 홈이나 비슷한 시술에 연결하지 않고 `missing` 또는 `unresolved`로 기록합니다.
5. 유효한 head 또는 편집·검증 가능한 사이트맵 중 **한 관리 경로**를 선택합니다. 본문 위젯의 태그만으로 완료 처리하거나 공통 head에 특정 시술 목록을 전 페이지용으로 넣지 않습니다.
6. 1차 정책은 **x-default 신규 지정 보류**입니다. 기본 이동 대상에 대한 운영 결정이 없기 때문입니다. 기존 값도 자동 삭제하지 않고 검토 대상으로 남깁니다. 사용자가 언어 선택 화면 또는 해당 콘텐츠의 기본 페이지를 승인하면 같은 묶음에 일관되게 적용합니다. x-default는 권장 사항이지 필수 태그가 아닙니다.
7. 첫 후보인 영어 소프웨이브 `/107`에서 hreflang을 바꾼다면 대응하는 한국어 `/139`, 일본어 `/107`, 간체 `/108`, 번체 `/139`까지 하나의 시험 묶음입니다. 영어 한 페이지 통과로 상호 연결 완료를 선언하지 않습니다.
8. 태국어는 수정 대상에서 제외합니다. 기존 태국어 연결이 발견되면 의존 관계와 미검증 상태를 적고 임의 삭제하지 않습니다.

소프웨이브의 내부 완료 조건은 **5개 언어 전체의 자기참조·상호참조 검증 통과**로 정합니다. x-default는 위 6번 정책에 따른 선택 항목입니다. 검증 진행률과 묶음 완료 여부를 따로 기록합니다. Google은 일부 언어가 빠져도 서로 참조하는 유효한 관계를 처리할 수 있다고 안내합니다. 따라서 일부 정상 관계까지 “전체 0% 유효”로 표현하지 않습니다. 영어 한 페이지만 고쳐도 상대 페이지에 이미 올바른 역참조가 있다면 그 관계가 복구될 수 있으므로, 실제 양쪽 출력을 검사해야 합니다.

자기참조·상호참조·표기·출력 방식의 기준은 [Google 다국어 안내](https://developers.google.com/search/docs/specialty/international/localized-versions)를 따릅니다. 문자 체계 선택, x-default 보류, 시험 묶음은 이번 프로젝트의 운영 결정입니다.

## 3. 이번 네이버 범위

이번 범위는 **서치어드바이저 기반 웹사이트 기술 검증**입니다. 플레이스 운영, 블로그 발행, 리뷰 확보, 광고와 지역 노출 전략은 별도 후속 과제입니다. 어느 채널에서 실제 유입이 큰지는 분석 자료 없이 단정하지 않습니다.

| 항목 | 검사와 결과 기록 |

| 사이트맵 | 각 사이트의 제공 URL·응답·구문·소유 호스트·대상 페이지 포함 여부 검사 |
| RSS | 유효한 피드와 실제 게시물이 있을 때만 적합성 검토. 필요 없는 사이트에 의무 생성하지 않음 |
| 제출 상태 | 기존 접수 결과는 읽기 확인. 신규 제출 필요 목록을 만들고 승인 후 담당자가 제출 |

## 4. 화면·기능·속도 판정

### 측정 조건

변경 대상 URL마다 모바일과 PC를 나눠 **변경 전 5회, 변경 후 5회** 측정합니다. 각각의 중앙값을 비교하고 전체 원자료를 보관합니다. 기기·브라우저 버전, 화면 크기, 네트워크·CPU 제한, 캐시 정책, 로그인·동의 상태, 로드 대기시간, 조작 순서와 측정 도구 버전을 고정합니다.

측정 오류가 난 회차는 이유를 남기고 동일 조건으로 보충합니다. 불리한 결과를 단순 이상치로 지우지 않습니다. 페이지가 바뀌거나 조건을 맞출 수 없으면 비교 불가로 보류합니다.

### 반려와 보류 기준

| 항목 | 판정 |
|---|---|
| LCP: 주요 화면이 나타나는 시간 | 변경 후 중앙값이 변경 전의 **1.10배를 초과하면 반려** |
| CLS: 화면이 흔들리는 정도 | 변경 후 중앙값 **0.1 초과 시 반려** |
| 작은 악화 | LCP가 0~10% 증가하거나 CLS가 악화되면 자동 통과하지 않고 전후 각 5회 추가 비교. 변경에 따른 재현 가능한 악화는 반려 |
| 기준선부터 CLS > 0.1 | 기존 문제로 별도 기록하되 위 기준의 통과로 처리하지 않음. 임의 디자인 수정으로 해결하지 않음 |
| 디자인 | 같은 화면 조건의 전후 비교에서 의도하지 않은 위치·크기·간격·폰트·색상 변화가 없어야 함 |
| 기능 | 메뉴·언어 이동·FAQ·슬라이더·상담 링크 유지. 실제 예약·결제·메시지 제출은 제외 |
| 증거 부족 | 통과가 아니라 보류. 측정 없는 “속도 유지” 금지 |

위 디자인 기준은 기술 SEO 변경에 적용합니다. 이미지 시험에서는 승인된 해당 슬롯의 이미지 변화만 허용하고, 주변 배치·크기·기능·속도의 악화는 허용하지 않습니다.

+10%는 공식 SEO 기준이 아닌 **내부 반려선**이며 10%까지 느려져도 좋다는 허용치가 아닙니다. CLS 0.1은 공식 좋은 경험 기준을 참고했지만, 공식 현장 평가는 방문 데이터의 75백분위이고 여기의 실험 중앙값과 같지 않습니다. 현장 데이터가 있으면 별도 항목으로 비교합니다. [CLS 공식 안내](https://web.dev/articles/cls)

새 외부 라이브러리, 반복 타이머, 전역 DOM 탐색, 불필요한 네트워크 요청은 추가하지 않습니다. 동일 조건의 측정만으로 모든 실제 방문 환경에서 악화가 없음을 증명할 수는 없으므로, 승인된 변경 뒤에도 이상 징후와 복구 기준을 기록합니다.

## 5. 개선 목표와 관찰 지표

기술 수정 완료와 검색엔진 반영 완료를 분리합니다. 검사 실패 URL을 분모에서 빼거나 hreflang을 전부 제거해 오류 0건으로 보고하지 않습니다.

| 지표 | 기준선 | 목표·확인 방법 |
|---|---|---|
| 복수 title 페이지 | 77 / 479 | 고정 479 URL 전체 재검사에서 0페이지. 추가 요소 143 → 0도 함께 검사 |
| 복수 title 작업 단위 | 언어와 위젯 ID 조합 143개 | 143위젯의 원문 대조·제안·시험·반영 상태를 각각 집계. 페이지 수는 영향 범위로 별도 표시 |
| 확인된 잘못된 언어 이동 | 소프웨이브 연결 3개가 404 | 3 → 0. 링크·목표 콘텐츠·최종 200을 함께 검증 |
| hreflang 오류 | 전체 수는 아직 미집계 | 확정 대응 묶음의 자기참조·상호참조·코드·200·대표 주소 충돌 오류 0건. 검사 페이지/전체 대상 페이지, 누락 묶음 수도 병기 |
| 홈 주소 신호 | 5쌍, 10 URL이 각자 자기참조 | 언어별 대표 주소 결정 5/5 및 지원 가능한 신호의 정렬. 불가능한 항목은 잔여 이슈로 공개 |
| GSC 페이지 색인 | 실제 자료 미확인 | 색인 대상 대표 URL 수, 색인된 대상 수, 미색인 사유의 전후 변화 기록 |
| Google 선택 canonical | 루트·home 중복 색인 여부 미확인 | 10 URL의 URL 검사로 선택 주소·수집일·색인 상태 기록, 대표 주소 결정과 대조 |
| 네이버 기술 검증 | 호스트별 상태 미확인 | 5개 호스트의 등록·수집·사이트맵·RSS 해당 여부와 제출 상태를 빠짐없이 기록 |

현재 479는 1차 공개 HTML 분석 집합이지 전체 관리자 페이지 수가 아닙니다. 숨김·미게시·신규 페이지는 별도 추가 집합으로 관리합니다. 기존 URL이 승인된 이동·삭제 대상이 돼도 원래 행과 사유를 남기고 대응 최종 페이지를 검사합니다. 미검사·응답 실패는 정상으로 계산하지 않습니다.

색인 수가 무조건 증가해야 성공하는 것은 아닙니다. 중복이 정리되면 총수는 줄 수 있습니다. 중요한 대표 페이지의 색인 여부와 제외 사유로 판단합니다. GSC 전체 보고서와 개별 URL 검사를 구분합니다. [Google 페이지 색인 보고서](https://support.google.com/webmasters/answer/7440203)

반영일 기준 2·4·8주를 검토 시점으로 제안합니다. 이는 재수집·색인의 완료 기한이나 자동 알림 예약이 아닙니다. 접근 권한이 없거나 검색엔진이 아직 재수집하지 않았다면 관찰 대기로 남깁니다.

## 6. 관리자 원문 백업

기본 보관 위치는 해당 작업 PC의 다음 **비공개 로컬 폴더**로 정합니다.

```text
%LOCALAPPDATA%/BeautyBlossom/seo-aeo-private/admin-backups/
  <capture_id>/<site>/<change_id>/
    original.txt
    metadata.json
    restore.md
    screen.png        필요한 경우만
```

저장소·워크트리·OneDrive 폴더 밖입니다. 이 위치를 지정한 것이 실제 백업 완료나 암호화 완료를 뜻하지는 않습니다. 다른 PC에서 작업할 때는 사용자 관리의 암호화된 전달·2차 보관 방법을 먼저 정하고 파일 해시를 대조합니다. 비밀 원문을 이슈·채팅·공개 링크에 붙이지 않습니다.

- `original.txt`: 관리자가 입력한 원문을 UTF-8로 저장합니다. 들여쓰기·개행을 임의 정리하지 않습니다. 자동 포매터를 사용하지 않습니다.
- `metadata.json`: 백업 ID, 언어·URL·위젯/필드, 수집 시각, 원본 위치, 인코딩·개행, SHA-256, 공개 반영 범위, 수집·재확인 방법을 기록합니다.
- `restore.md`: 정확한 복원 필드, 저장·게시 영향, 원문 재확인 방법, 복구 시험 결과를 기록합니다.
- 공통 head/body/footer와 그 밖의 변경 대상 설정은 필드별 별도 변경 ID를 사용합니다.

공개 저장소에는 민감정보 검토를 마친 **백업 색인·해시·복원 상태·최소한의 수정 차이**만 올립니다. 색인 필드는 `backup_id, site, change_id, field, relative_archive_id, sha256, captured_at, verified_at, restore_test_status`입니다. 관리자 원문·before/rollback 전체 파일과 화면의 인증 정보는 올리지 않습니다. 공개 HTML 사본은 관리자 복구본이 아닙니다.

0단계 통과 조건은 변경 대상의 누락 없는 수집, 다시 읽은 원문의 해시 일치, 정확한 복원 위치 확인, 승인된 격리 공간에서의 복구 시험, 사용자 관리 2차 사본 확인입니다. 준비되지 않은 항목은 보류합니다. 이후 새 필드·위젯을 추가로 다룰 때도 해당 원문을 먼저 확보합니다.
