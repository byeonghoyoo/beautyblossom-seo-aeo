# 그림으로 보는 프로젝트

## 무엇을 다루는가

```mermaid
flowchart TB
    G[목표<br/>검색엔진이 정확히 이해하고<br/>방문자는 그대로 편하게 사용]
    G --> S[검색 정보]
    G --> M[다국어 연결]
    G --> I[이미지 품질]
    G --> Q[안전 검수]

    S --> S1[제목·설명·대표 주소]
    M --> M1[같은 시술의 실제 국가별 주소]
    I --> I1[인물 이미지·타이틀 이미지·대체 설명]
    Q --> Q1[디자인·기능·속도·복구]
```

## 누가 무엇을 하는가

```mermaid
flowchart LR
    U[사용자<br/>범위와 최종 승인] --> C[Codex<br/>조사·기획·검수]
    C --> D[Claude Code<br/>승인된 항목 구현]
    D --> C
    C --> U
    U -->|승인 후| W[아임웹 반영]
```

## 안전하게 바꾸는 흐름

```mermaid
flowchart TD
    P[-1 제어 범위를 실측한다] --> Q{안전한 경로가 있는가?}
    Q -- 아니오 --> R[해당 항목 대안 검증·보류]
    Q -- 예 --> A[비공개 원본을 보관한다]
    A --> B[문제 유형과 위젯을 선택한다]
    B --> C[변경안을 먼저 본다]
    C --> D[별도 작업방에서 수정한다]
    D --> E[검색 정보 확인]
    E --> F[모바일·PC 화면 확인]
    F --> G[메뉴와 상담 기능 확인]
    G --> H[PC·모바일 전후 각 5회 비교]
    H --> I{문제가 없는가?}
    I -- 아니오 --> J[원본으로 복구]
    J --> B
    I -- 예 --> K[사용자 승인]
    K --> L[실제 반영]
    L --> M[Google·네이버 결과 관찰]
```

## 이미지 교체 흐름

```mermaid
flowchart LR
    A[현재 이미지 목록] --> B[교체 후보]
    B --> C[교체 이유 기록]
    C --> D[같은 비율의 시안]
    D --> E[모바일 잘림·용량 확인]
    E --> F{승인?}
    F -- 아니오 --> D
    F -- 예 --> G[원본과 교체 기록 보관]
    G --> H[한 위치만 시험 반영]
```

“오래됐다”거나 “AI처럼 보인다”는 말만으로 교체하지 않습니다. 제작 근거, 어색한 부분, 페이지 역할, 저작권·초상권, 속도 영향을 함께 기록합니다.

단계별 기간과 기본 9~10개 PR은 [작업 순서](04-WORKFLOW.md), canonical 분기·다국어 규칙·성능 수치는 [실행·검수 기준](07-IMPLEMENTATION-POLICIES.md)을 따릅니다. 네이버는 웹사이트 기술 검증만 별도 트랙으로 진행합니다.
