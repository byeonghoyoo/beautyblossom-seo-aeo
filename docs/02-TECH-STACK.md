# 2. 사용 도구

전문용어보다 각 도구가 왜 필요한지를 기준으로 정리합니다.

| 도구 | 쉬운 설명 | 이 프로젝트에서 하는 일 |
|---|---|---|
| 아임웹 | 실제 홈페이지 관리자 | 검색 설정과 페이지별 코드·이미지를 확인하고, 승인된 변경만 반영 |
| GitHub | 기획안과 변경 기록을 보관하는 금고 | 누가 무엇을 왜 바꿨는지 기록하고 이전 상태로 돌아갈 근거 제공 |
| Git 워크트리 | 본 작업과 검토 작업을 분리한 작업방 | 안정된 `main`과 기획·수정 브랜치가 섞이지 않게 보호 |
| Python | 반복 검사를 맡는 도구 | URL·제목·설명·대표 주소·이미지·구조화 정보 목록 생성 |
| 브라우저 검사 | 실제 방문자 화면 확인 | 원본 코드뿐 아니라 실행 후 화면과 기능 확인 |
| Mermaid | GitHub에서 바로 보이는 흐름도 | 기획과 작업 순서를 일반인이 이해하기 쉽게 표시 |
| 이미지 제작 도구 | 승인 후 새 이미지를 만드는 도구 | 교체 후보에 맞는 시안을 제작하되 기존 비율과 용량 기준 유지 |

## 새 도구를 함부로 늘리지 않는 이유

아임웹 사이트는 이미 큰 공통 CSS·JavaScript와 외부 리소스를 사용합니다. 새 라이브러리와 추적 스크립트는 속도와 충돌 위험을 늘릴 수 있으므로, 검색 정보 수정은 가능한 한 아임웹의 기존 설정과 짧은 정적 메타데이터로 처리합니다.

## 검색 기준

- Google Search Central의 다국어·제목·대표 주소·이미지·구조화 데이터 지침
- 네이버 서치어드바이저의 검색 최적화·콘텐츠 마크업 지침
- 아임웹에서 실제로 출력된 HTML과 실행 후 브라우저 DOM

제3자 SEO 점수는 참고할 수 있지만 공식 기준과 실제 출력보다 우선하지 않습니다.
